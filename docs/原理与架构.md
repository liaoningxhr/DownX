# DownX 运行原理与架构

一句话：**链接进来 → 认出平台 → 拿直链（可能音视频分离）→ 带断点续传下载 → 必要时合成 → 写进相册 → 生成缩略图 → 列表展示。**

---

## 1. 总体数据流

```
用户在首页粘贴文本/链接
   │
   ├─ MainActivity.detect(text)          ← 判断平台（域名 / 短链 / 分享口令）
   │
   ▼
平台 Fetcher（解析）                     ← 只做网络请求 + 解析，不碰文件
   │  BiliFetcher / YoutubeFetcher / IgFetcher / XhsFetcher /
   │  TweetFetcher / FbFetcher / PinFetcher / TikTokFetcher /
   │  ShortVideoScraper（抖音快手，WebView 嗅探）
   │
   ▼  统一产物 TweetFetcher.Result
   │     items[]: { url 直链, label 画质名, thumb 封面, audioUrl 音频直链? }
   ▼
MainActivity 弹画质选择（LayoutPicker / 底部弹层）
   │
   ▼
DlService（前台 Service，独立线程）       ← 真正干活的地方
   │  ├─ 普通 HTTP：Range 续传
   │  ├─ HLS：分片逐片下载 + 记录每片字节数
   │  └─ dash/分离流：先下画面，再下声音
   │
   ▼
Mux.remux()（仅当有 audioUrl）            ← MediaExtractor + MediaMuxer 重封装
   │
   ▼
Store.write() → 相册（MediaStore）+ 私有目录兜底
   │
   ▼
ThumbLoader 抽帧 → 缓存封面；HistoryStore 记一条历史
   │
   ▼
MainActivity 列表（竖屏/横屏抽屉、失效检测）→ PlayerActivity 播放
```

## 2. 平台解析策略（每个平台的"命门"）

| 平台 | 走什么接口 | 关键点 |
|---|---|---|
| **B 站** | `api.bilibili.com/x/player/playurl` | 未登录最高 720P（durl 单文件）；登录后带 `fnval=4048&fourk=1&platform=pc` 拿 dash，video+audio 分开，必须双流合成 |
| **YouTube** | InnerTube `player` 接口（ANDROID / IOS 客户端） | 只给 1080P 以内的 adaptive；`signatureCipher` 要解；音视频天然分离 |
| **Instagram** | `i.instagram.com/api/v1/media/{id}/info`（appapi）优先，失败退 `www.instagram.com/api/v1` | **裸请求必 401**：先 GET 首页拿 `csrftoken/mid/ig_did` 做匿名预热；dash 里必须同时拿到 audio 的 BaseURL，否则只有画面没声音 |
| **X / Twitter** | `cdn.syndication.twimg.com/tweet-result` + API | 从 `video_info.variants` 按 bitrate 排档 |
| **小红书** | 笔记页 `window.__INITIAL_STATE__` | 视频取 `originVideoKey`，图集取原图；要带 Referer |
| **抖音 / 快手** | **WebView 打开官方分享页，用平台自己的 JS 签名** | 免签名接口（iteminfo / _ROUTER_DATA / INIT_STATE）全部返回空包，**已放弃**；靠拦截 WebView 的网络请求拿真地址 |
| **Facebook** | 官方 `plugins/video.php` embed 页 | 页面里有 hd/sd 直链，匿名可用 |
| **Pinterest** | 帖子页 `video_list`（V_720P / V_HLSV4） | og:image 当封面 |
| **TikTok** | `tikwm.com` 公开接口 | 免登录，可拿无水印 |

### 抖音/快手嗅探（ShortVideoScraper）要点

- 用不可见 WebView（340×600dp，alpha=0.01，translationY 挪到屏幕外），加载候选页；
- 每 300~1100ms 轮询一次 `WebView` 里已加载的资源 / 注入 JS 读 `performance.getEntries()`；
- 命中判定不能看 `.mp4` 后缀（抖音流地址没有后缀），要看 CDN 域名
  `douyinvod / kwaicdn / yximgs / ksycnd` 或参数 `mime_type=video_mp4`；
- 打分：`playwm`（带水印）< `play`（无水印）；
- **自学习**：命中后把当前候选页序号存 `Prefs.svPage(platform)`，下次直接从这条开始；
- **代计数 `gen`**：换候选页时 `++gen` 并 `removeCallbacksAndMessages(null)`，
  旧一轮的定时探测必须作废，否则两条链并行狂探导致卡顿；
- 验证页（含"安全验证/请拖动滑块/verify-center"）和死页（标题只有"抖音/快手"）立刻换页；
- 总预算 22 轮，前 3 轮 300ms 密探。

## 3. 下载层 DlService

```java
private static final class Task {           // 每条下载独立运行态
    volatile boolean paused, canceled;      // 避免两条并发时全局开关互踩
    volatile HttpURLConnection conn;
    final String name;
}
private void gate()                          // 每个循环/回调里调用：canceled 抛异常，paused 时轮询等待
```

- **前台 Service** + 通知栏进度，切到后台不被杀；
- `gate()` 是暂停/取消的唯一入口，**任何长循环里都要调**，否则取消不生效；
- `cancel()` 直接 `conn.disconnect()` 让阻塞的 read 立刻抛异常醒来；
- 进度区间固定映射：画面 0-62 → 声音 62-80 → 合成 81-94 → 保存 96-100；
- `showProgress` 做**单调钳制**（`if (pct < lastShownPct) pct = lastShownPct`），
  否则子任务切换时会看到进度倒退。

## 4. 断点续传 Parts

目录：`/sdcard/Android/data/com.downx.app/cache/parts/<hash>/`

- `state.txt` 键值对：`id / url / name / kind / referer / pick / sig / offs / segV / segCountV / lenV / vDone / aDone`
- 数据文件与 state 同目录；**每下完一个分片就 `Parts.save()` 一次**（不是等整个文件下完）；
- 重新下同一条链接时 `Parts.load()` 命中 → 用 `Range: bytes=<已有长度>-` 续写：
  - 返回 **206** → `append` 续写
  - 返回 **200** → 服务器不支持 Range，截断重来
- `sig` 变化（链接/画质变了）→ 清空 `offs/segV`，重新开始；
- `offs` 是**每个分片的字节数**（逗号分隔），HLS 重封装时必须按分片边界逐段抽，
  否则 `MediaExtractor` 会在接缝的时间戳跳变处提前收工（踩过：71 MB 源只转出 9.5 MB，播放只有声音）。

## 5. 合成层 Mux（音视频分离的场景）

```java
public static void remux(File in, long[] segLens, File out, Progress cb)
```

- 用 `MediaExtractor` 找视频轨 + 音频轨，`MediaMuxer` 写 MP4；
- `segLens != null` 时**按分片逐段** `seekTo` + 读，避免接缝问题；`null` 则整文件模式；
- `parseTsAac()` 自己解析 TS 里的 ADTS 帧（要锁定音频 PID 那包一起收进 acc，
  读循环条件必须 `fill - pos < 188` 才读新数据）；
- 只要 `audioUrl` 存在就走合成；**拿不到音轨就退回单文件版本，绝不输出无声视频**。

验证产物有没有声音：直接查 MP4 box 里有没有 `vide` / `soun` / `mp4a` 字符串。

## 6. 存储层 Store

- 目录分两类：隐藏目录（相册看不到）和 `publicDir`（相册可见，MediaStore Movies/Pictures + DownX）；
- 隐藏目录**不是** `getExternalFilesDir`，而是 `Android/media/<包名>/{Movies,Pictures}/DownX`：
  - `Android/data/<包名>` 卸载时会被系统整目录删掉，下载的视频跟着消失；
  - `Android/media/<包名>` 卸载不删（系统保留），App 自己免权限读写；
  - 该根目录放一个 0 字节 `.nomedia`，MediaStore 扫描时跳过整棵目录，相册仍然看不到；
  - Android 10 及以下这一步不可写，`mediaRoot()` 探测失败就回退老位置，设置页文案如实提示。
- `privateFile()` 定位"新位置优先、老位置兜底"，迁移没跑完也能正常播放/删除；
  写入一律走 `privateWriteTarget()`，绝不因为"同名文件已存在"又写回 `Android/data`。
- `upgradeStorage()`：启动后台线程执行 `migrateHidden()`（老文件搬家）+ `restoreHistory()`
  （把目录里有、历史里没有的文件补成记录，专治卸载重装后列表空白）。**每次启动都做一次对账**
  （v1.3.5 起不再用一次性 `restored` 标记：记录被顶掉后再也补不回来），
  用户主动删掉的文件名记在"已删除名单"里，对账时跳过，不会复活。
- 优先写相册（MediaStore），失败退回隐藏目录，列表里给"修一下/移动到相册"入口；
- `uriAlive()`：查 MediaStore 的 `DATA` 路径 `File.exists()`，
  防止"列表里有卡片但文件已被删"的假记录；
- `migrate()` / `moveOne()`：隐藏 ↔ 相册批量迁移；
- `probeOrientation()`：读视频宽高判断竖/横屏，喂给首页的"竖屏/横屏"筛选；
- 去重用 `key`（平台 + 作品 ID），不靠文件名。

### 6.1 记录存储（HistoryStore / RecLog / RecFile）

v1.3.6 起记录不再存 SharedPreferences 的 JSON 字符串，改成**只追加的日志**：

- `filesDir/history/items.log`：一行一条记录，制表符分隔、字段全转义，首字段是格式版本号；
- 新增记录、改一条记录的方向标记 = **追加一行**（O(1)）；加载时同 key 后写覆盖先写，
  位置仍按第一次出现（`RecLog.merge`）。文件里有同一条的多个版本是设计如此；
- 删单条 / 清空 / 去重 / 拖拽排序 / 超上限清理才整体重写：`tmp → rename` 原子替换（`RecFile`）；
- `RecFile.read()` 发现主文件不在而 `.bak` 在，会先恢复 —— 覆盖"两次改名之间断电"的现场；
- 老数据迁移：`items.log` 不存在时读老 JSON 数组写入，原文另存 `legacy-v1.json` 后清空老 prefs；
- 分层原因：`RecLog`（编解码 + 合并）和 `RecFile`（落盘）都是纯 Java，`tests/history` 能在主机上
  跑真实文件 IO（82 项），`HistoryStore` 只留 Android 相关的缓存与 Context 适配。

## 7. 展示层

- **ThumbLoader**：0.3/1.2/2.5/4/7 秒逐点抽帧，用亮度+对比度打分挑最清楚的一帧；
  片头全黑时按全片 8/15/25/40/55% 补帧。缓存 key 带版本前缀（`v4|uri|kind|fallbackUrl`），
  改算法时**必须改前缀**，否则旧的黑封面会一直命中缓存。
- **MainActivity**（2615 行，最大的文件）：三套列表排版 `buildDrawerCell / buildCell / buildListRow`，
  改卡片样式要**三处都改**；方向筛选 `dirSwitch/dirChip`；失效卡片有独立排版。
- **PlayerActivity**：自绘播放控制，支持锁定、倍速、手势；`hideTip` 到点无条件收起。
- **Zoomer**：播放器/图片查看器共用的双指缩放器（`scale/translation` 走 View 自带变换，
  支点固定在视图中心）。规则是「第二根手指落下就接管整段手势」，因此它排在所有
  单指手势（轻点显隐、按住加速、左右滑切换、单击关闭）之前被询问。
  图片查看器接它时要给 GestureDetector 补 ACTION_CANCEL，播放器要撤掉加速计时器。
- **PhotoViewerActivity**：查看器（左右滑切图、长按菜单、多选平铺）+ 同一个 Zoomer。

## 10. 线路：不内置检测，交给用户和 VPN 客户端

> 2026-11-09 决定：曾经实现过的 `NetRoute`（设置页「网络线路」一行 + 解析失败追加线路建议）
> 已整体移除，原因见下。

### 10.1 Android 不允许 App 自己选线路

系统级 VPN 一旦连上，本 App 的全部 socket 都会被内核按 UID 送进 VPN 的 tun 口；
同时 `getAllNetworks()` **不会把底层的 Wi-Fi / 移动网络暴露给 App**。

- `Network.bindSocket()` / `bindProcessToNetwork()` 只能在 App *看得到* 的网络里选，
  被 VPN 藏起来的底层网络根本不在候选列表里；
- 「一个 App 里国内链接走直连、境外链接走 VPN」在系统 VPN 场景下**做不到**；
- 真要分流只有两条路，都在 App 之外：VPN 客户端开「分应用代理 / 分流规则」，或手动开关。

### 10.2 为什么连"检测 + 提示"也不做

检测本身是能做（`TRANSPORT_VPN` 就能判断我们的流量走没走 VPN），但产品上不划算：

- **用户本来就会**：能装 VPN 的人知道下国内平台要关、下国外平台要开。多一行提示是噪音。
- **说不了准话**：`PROXY` 只说明流量进了 VPN，不代表节点在境外。文案只能写"走代理"，
  这种模糊表述比不说更容易让人误解。
- **误判成本高**：帖子被删、链接失效、平台风控都会失败，硬扯"检查代理"会让人反感；
  只对网络层错误过滤也仍会踩到平台自己的 403/风控页。
- **界面代价**：设置页多一行带胶囊和副标题的条目，与"账号区"抢注意力，纯属画蛇添足。

### 10.3 现状与边界

- 设置页**没有**线路相关的任何入口；解析失败的提示只说真实原因（登录墙、帖子不可用、
  连不上）。
- 线路怎么走完全由系统决定：用户开 VPN 就走 VPN，关了就直连。
- 因此**不要**在这里加 `bindProcessToNetwork` / 自建 `Network` 之类的"智能选路"，
  系统 VPN 场景下必然失败，而且会引入难查的连接泄漏。
