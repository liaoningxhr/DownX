## 二、三条命令（日常全部操作）

```sh
# 1) 构建（约 55 秒）
sh F:/DownX-Studio/scripts/build.sh

# 2) 签名并出包 → releases/DownX-v2.9.1.apk
sh F:/DownX-Studio/scripts/sign.sh 2.9.1

# 3) 装机调试（先连 USB/无线调试）
INSTALL=1 sh F:/DownX-Studio/scripts/sign.sh 2.9.1
```

改版本号只改两个地方（`app/app/build.gradle`）：

```gradle
versionCode 39        // 每版 +1，必须递增
versionName "2.9.1"   // 显示用
```

> 签名用的是 `C:\Users\Administrator\.android\debug.keystore`（口令 android，别名 androiddebugkey）。
> 换机器要把这个 keystore 一起带走，否则装不上（签名不一致会提示"应用未安装"）。

## 三、技术底线（别破坏）

1. **零第三方依赖**：不用 AndroidX、不用广告/统计 SDK，`dependencies {}` 是空的。
   好处是 APK 只有 400 KB、启动快、不会被商店 SDK 拖累。
2. **纯 Java + 原生 View**：没有 Compose、没有 Kotlin。改 UI 就改 xml + findViewById。
3. **minSdk 24 / targetSdk 34 / Java 17**。
4. 所有网络请求走 `Net.java`（HttpURLConnection 封装），不引入 OkHttp/Retrofit。
5. **不要动下载主干的进度区间映射**（0-62 画面 / 62-80 声音 / 81-94 合成 / 96-100 保存），
   前端进度条和断点续传的百分比都依赖它。

## 四、支持的平台（对应 HelpActivity 的清单）

| 平台 | 画质 | 解析方式 |
|---|---|---|
| B 站 | 720P；登录后 1080P，大会员 4K | 官方 playurl，dash 双流 |
| YouTube | 最高 1080P | InnerTube 客户端接口，dash 双流 |
| 抖音 / 快手 / TikTok | 无水印原片 | WebView 嗅探官方页面 |
| 小红书 | 无水印视频 / 图集原图 | 页面 state 解析 |
| Instagram | 帖子 / Reels，免登录 | appapi + webapi 双通道 |
| X（Twitter） | 原始画质 | syndication + API |
| Facebook / Pinterest | 公开内容 | embed 页 / 页面 video_list |

改功能后**记得同步更新** `HelpActivity.build()` 里的平台清单文案（用户明确要求说明书和实际能力一致）。

## 五、加一个新平台怎么做

1. 在 `app/src/main/java/com/downx/app/` 新建 `XxxFetcher.java`，输出统一结构
   `TweetFetcher.Result`（含 items：url / label / thumb / audioUrl）。
2. 在 `MainActivity` 的链接分发处（`detect` / `startXxx`）加分支。
3. 在 `TweetFetcher` 的白名单/分发里登记域名。
4. 在 `AndroidManifest.xml` 加 host（如果要支持从别的 App 分享进来）。
5. 在 `HelpActivity` 平台清单加一行。
6. 真机验证：解析 → 下载 → 相册能看到 → 播放有画面有声音。
