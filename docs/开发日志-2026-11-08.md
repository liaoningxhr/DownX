## DownX（自建无广告视频下载器 Android APP）

- 起因：用户手机上的 Downmio（Twitter/IG 下载器）广告太多，要求做一款功能对等、无广告的 APP；明确要真 APK，不要 PWA。
- 项目：`F:\WorkBuddyDownloader\2026-11-08-09-54-39\DownX`（包名 `com.downx.app`，纯 Java + 原生控件，零第三方依赖、零广告 SDK）。
- 构建工具链全部装在 F 盘：`F:\android-build\{jdk,gradle-8.7,sdk,gradle-home,userhome,pylibs}`；Gradle 8.7 + AGP 8.3.2 + JDK 17，compileSdk 34 / minSdk 24。

## 接口实测结论（2026-11-08，Playwright + 系统代理 127.0.0.1:10808）
- Twitter：
  - `api.twitter.com/1.1/statuses/show.json`（访客 token）已废弃，恒 404，不要指望。
  - `cdn.syndication.twimg.com/tweet-result?id=..&token=..` 可用，token 算法 `((id/1e15)*PI).toString(36)` 去掉 0 和点；Java 移植结果与网页端完全一致（id=20 → `6dq1a2xwd93jfti`），能拿全部清晰度 → 作为首选通道。
  - `api.fxtwitter.com/status/{id}` 可用，作为第二通道。
- Instagram：
  - `i.instagram.com/api/v1/media/{pk}/info/` 匿名 403；`?__a=1` 404；embed 页是 JS 壳（HTTP 抓不到数据）。
  - 但**用浏览器（WebView）加载 `/p/{code}/embed/captioned/` 后，`<video>.src` 就是可直连下载的签名 mp4**（reel 和普通视频都验证通过），`scontent-*.cdninstagram.com` 直链无需 Cookie，仅需 UA/Referer，2MB 测试文件下载成功。
  - 元数据选择器：`.UsernameText` 取用户名，`.Caption` 取正文（需剔除首行用户名与 "View all N comments"），封面用 `video.poster`。
  - 结论：IG 必须走 WebView 内取，HTTP 通道无效。登录态（Cookie）通道保留给私密/受限内容。
- 环境：`F:\android-build\pwtest` 装了 Playwright + Chromium（浏览器在 `F:\android-build\pw-browsers`），可复用于后续网页验证。

## 19:10-20:55 PH 无声 + 播放器失效记录（v2.7.2）
- 「播放没声音」排查结论（logcat 实锤）：

  3. python 解 box：音轨只有 5875 个样本（应 ~27000）、平均 2614 字节/样本（应 ~300）、
     音轨时间轴 260s vs 视频 627s —— 系统的 MPEG2TSExtractor 抽 TS 里的 AAC 会丢一半以上的帧，
     MediaMuxer 按坏表写出 mp4。相册播放器容忍坏表所以「有声」，VideoView 直接判 EOS 所以无声。
  另外两条「无法播放」是**孤立记录**：文件已被删（相册里没了）但 HistoryStore 记录+缩略图还在，
  缓存的 content://media/... uri 打不开 fd。

  裸 AAC 帧写临时 .aac + 按帧序(1024采样)重排时间戳（PES PTS 回跳时整体上抬）→
  AudioSpecificConfig 2 字节做 csd-0 → 与视频按 PTS 归并写 muxer。
  独立 Java 验证：184 帧=4.267s 与 EXTINF 完全一致、严格单调、帧间隔误差 15µs。
